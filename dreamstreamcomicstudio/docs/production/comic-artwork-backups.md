# Comic Studio artwork backups

The production `dreamstream-comic-artwork-backup` Cloudflare Worker copies objects from the Comic Supabase project's `comic-assets` and `comic-private` buckets to the private R2 bucket `dreamstream-comic-artwork-backup`. It checks both buckets at 00:07, 06:07, 12:07 and 18:07 UTC. A complete scan takes additional time. A file created and deleted between scans may never reach the archive. Database backup and point-in-time recovery cover separate data. This archive does not contain Chat, accounts, credentials or the full project database.

The initial production scan finished on 23 November 2026 at 16:17 UTC. The source and archive each contained 1,204 artwork objects and 294,842,715 bytes. Their inventory digests matched across bucket, object ID and byte length. Each object had a recovery manifest. The separate restore check read back a 61,614-byte sample and removed its temporary copy. The private source bucket was empty on this scan.

## Director draft artwork

New Director renders and derived artwork, including their 480- and 1080-pixel previews, use a `draft-v1-<uuid>` basename in the existing image lane. The application resolves that basename in the private bucket and signs owner previews for five minutes. Publication copies the approved pages into its existing public `pub/` folder. Both locations remain covered by the backup schedule.

Before deploying the writer, verify the private bucket accepts WebP, has no client read or write policy and allows 40 MiB files at both project and bucket level. The idempotent `server/sql/comic_private_draft_capacity.sql` raises only the existing private bucket’s per-file limit as needed. Keep the versioned path reader deployed to open, restore or publish artwork written by this version. A rollback that stops new private writes must retain this read support. Earlier draft originals and previews keep their original bucket and cached URLs; moving them requires a separate verified migration.

## Operation

One Cloudflare Queue consumer processes up to 30 records per batch, with three concurrent source downloads. Page advances use a conditional R2 checkpoint write. A retry revisits the same page and reuses previously completed file versions. Workers.dev, preview URLs and public bucket domains are disabled. No HTTP route starts a scan or serves a backup. Worker request tracing and subrequest logging are disabled because signed source URLs are sensitive.

The Supabase Edge Function `comic-artwork-backup-source` requires a valid project JWT and a separate random reader token restricted to this gateway. Its service credential stays inside Supabase. The Worker uses its own `BACKUP_TOKEN` secret and the public project anon key. The service-only PostgreSQL function `comic_artwork_backup_manifest(text,uuid,integer)` validates the bucket, returns up to 50 records and sorts by object ID. The source signs the returned paths for ten minutes. Copying only reads the source.

## Monitoring and recovery

Use a Cloudflare administrator or restricted R2 operations credential to inspect `control/status.json` in the **private** archive. It contains the scan timestamps, per-bucket counts and bytes, and the latest restore-check result. `control/last-error.json` contains a time and a fixed error code. An error older than a subsequent successful checkpoint is historical. A scan that hasn't completed after two scheduled intervals, a newer error, or a failed restore check needs investigation. The Cloudflare Queue is both the scheduler's destination and the private manual entry point. An authorized operator can send the JSON message `{"scan":true}` to resume a failed scan. A complete fresh scan ignores a redundant trigger. After five retries, the next scheduled trigger resumes from the last durable checkpoint.

Each archived source version has a content object under `art/<bucket>/<source UUID>/<version hash>` and a private manifest under `manifests/<bucket>/<source UUID>/<version hash>.json`. The manifest records its original name, source version, size, MIME type, SHA-256 checksum and backup time. It contains no signed URL. After storing a new version the Worker reads the bytes back and checks their SHA-256. Each complete nonempty scan also copies one randomly sampled archived object to a random private `verification/` path, reads and hashes that copy, then removes only the temporary check object. A future empty scan has no restore sample and reports that explicitly.

To recover a deleted source object, locate its retained manifest by source bucket and object UUID. If only the original path is known, an authorized operator may search manifests privately for that exact path. Select the version by its timestamp, copy its archived bytes into a separate private recovery location, and compare the manifest size and SHA-256 to that read-back before using the file. Confirm the original project's owner, destination bucket, path, permissions and intent before promoting recovered data. Restoring a file to its live path is a separate authorized operation. Do not make a recovery bucket or temporary URL public to inspect artwork.

Old versions remain in R2 after updates or deletions in Supabase. There is no automatic expiry of artwork or manifests. R2 storage and operations can therefore increase over time. A separately authorized permanent-erasure request must cover every matching archived version and manifest as well as the source. R2 is a separate vendor within the operator’s Cloudflare account. The archive does not supply an immutable legal hold or a copy in a second Cloudflare account.

## Deployment

Apply `server/sql/comic_artwork_backup_manifest.sql` and deploy `artwork-backup/source/index.ts` to the verified Comic project with gateway JWT verification enabled. Replace the single `__BACKUP_TOKEN_SHA256__` marker with the deployed reader digest from `artwork-backup/source/production-reader.sha256`. The digest is public configuration. The reader secret stays in Cloudflare. When rotating the token, generate it inside the secret-management context, update the Worker secret and source digest together, and verify the next private scan. The placeholder denies access.

The Worker, private R2 binding, single-concurrency queue and cron are described in `artwork-backup/wrangler.json`. Preserve the deployed `BACKUP_TOKEN` secret and disabled public/preview domains when updating it. Test source and archive behavior with `vitest run artwork-backup/source/index.test.ts artwork-backup/worker/index.test.mjs`. The SQL regression is `server/sql/tests/comic_artwork_backup_manifest.test.sql`.
